## Substitutions and gaps

- Pipeline cards use holdout records of the same kind instead of the demo examples (`docs/demo_ru/examples/ex1–4` =
  `ffpp_real:220__f0320`, `part_forgery:donor:454__f0140__mouth`, `alibaba:EyeEnlarging_90:17001`,
  `ffpp_fake:Deepfakes:154_386__f0164`): those are development-set records, and the final Chinese prompt `p3r1z` was run on
  the holdout only (dev has `p3r1`), so the demo examples have no final-design Chinese text.
- FakeVLM "genuine → fake": FakeVLM called 50 untouched originals fake, but our system has no record on any of those
  exact images (originals are only the `x0` side of pairs; the three originals that match an `ffpp_real` record were judged
  correctly by FakeVLM). Replaced by two identity-keeping commercial retouches that FakeVLM called fake (wrong under the
  real / fake / filter definition).
- "Number as words" (G10): G10 never fired on a real LLM output (0 in every p3 run), so the card shows an H4 catch
  ("number not in the record") from the p2en1 line instead.
- "Invented operation": no `H3.text:invented_op` hit exists in the stored outputs; the card uses an
  `H3:below_threshold_op` catch whose text treats below-threshold operations as applied.
- Missing fact: no `fake`-decision fallback exists in `holdout_p3en1_7b.jsonl`, so a `filter` record is shown.
- Contours are re-drawn with the `vlm_explain.overlay` rule (0.5 iso-line cyan, top-12 % boundary yellow, black
  under-stroke) at card resolution; the region box on the pair card is re-drawn with the `run_v3.face448` rule
  (the rendered VLM inputs in `v3_render/` were not kept, only their manifest).
